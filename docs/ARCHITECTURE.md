# Architecture

## Boundaries

The Flutter view reads a ChangeNotifier view model through Provider. The view model depends on an ExhibitionRepository interface. ApiExhibitionRepository decodes explicit Dart models from ApiClient responses. Only the API client knows HTTP. The normal application always uses the API; test fixtures are never imported by production code.

Laravel routes delegate to a controller and GetCuration action. Eloquent models remain internal; API Resources serialize all public content. Form Requests validate growing index queries. The FilesystemMediaUrlResolver interface separates URL generation from storage configuration. No public write endpoints exist, so no authenticated policies are needed yet. Future mutations must add authentication and policies before being exposed.

## Application flow

Bootstrap → load bounded home curation → identity/loading or retry → photograph/title reveal → Enter Exhibition → editorial home. The same hero artwork remains visible across the route transition. Flutter routes `/` and `/exhibition` are deliberately small; no gallery or artwork detail routes are claimed.

Tablet landscape uses a split editorial/image entrance and horizontal artwork sequences. Portrait/phone use stacked entrance content. Phones present work vertically. Layouts scroll to preserve scaled text instead of clipping it.

## Persistence and operations

PostgreSQL is the canonical database. UUID identifiers, foreign keys, bilingual display fields, publication timestamps, and deterministic development IDs establish the future domain. Timestamps use UTC. Stable local public URLs are generated by Laravel Storage; production can switch to an S3-compatible disk with a configured public CDN URL. Originals/private media must use a separate private disk in later phases.

The default queue is database-backed with jobs and failed_jobs migrations. No slow media operation occurs in an HTTP request. Seed media copying runs only in the CLI seeder. Image processing/indexing jobs are not invented before their use cases exist; future handlers must implement ShouldQueue.

## Reliability

Health reports process liveness. Readiness probes the DB and returns 503 on failure. It does not assert that sample content exists. Errors use one RFC 9457-shaped envelope with a server-generated request ID. Rate limiting applies to exhibition read routes (120/minute/IP). Curation queries exclude draft/future works, including hero relationships. Indexes paginate, while curation is bounded to six entries per section.

Structured JSON logs include request ID, method, path, status, and duration. Query strings and request bodies are not logged by the request middleware. Production must keep APP_DEBUG=false, set HTTPS/CORS/DB credentials, centralize cache/rate limits for multiple instances, and use its own deployment process. The built-in PHP server is development-only.

## Verification boundary

PHP runs in this workspace. Native PostgreSQL cannot initialize under its mapped root-only identity; verification used PGlite (PostgreSQL compiled to WebAssembly) behind a local wire-protocol server and PDO pgsql. This is useful database evidence, not a substitute for native PostgreSQL CI. Flutter startup was blocked by automatic approval review for a cloud metadata request. No alternative UI is passed off as the Flutter application.

## Phase 2 extension

Home retains its entrance and curation repository. `DiscoveryRepository` is a separate replaceable interface for collection/exhibition identities, paged streams, artwork details and photographer profiles. `ApiDiscoveryRepository` shares the existing ApiClient conventions and typed models. DiscoveryViewModel handles paging, retries and generation-based stale-response suppression. Views never construct HTTP clients or use fixture data.

Navigation: home → DiscoveryView → ArtworkFocusView. PageView.builder lazily builds gallery pages, keeps the page controller on the retained route and uses a stable PageStorageKey. Returning from focus preserves the exact gallery page/offset, loaded pages and filters without reloading the API. This is in-session navigation restoration; process-death/deep-link restoration is not yet implemented. Home artwork sequences also open the same focus view, with distinct Hero tags per section to avoid duplicate artwork collisions.

Only the next likely hero is explicitly prefetched. Focus initially reuses hero media, then upgrades to fullscreen after 700ms. Image cache is configured to 64 MiB / 40 entries at app bootstrap; live widget-held images can exceed this cache, so this is not a total-memory guarantee. Photography is always contained, never cropped. A local ShortlistRepository has asynchronous mutation methods and change notification so Phase 5 can replace its storage behind the same view interface.

Laravel discovery controllers orchestrate validation, GetArtworkStream, Eloquent and explicit resources. PublicContentCache performs representation revalidation after serialization. CLI BuildMediaRenditions performs image processing outside HTTP. No semantic provider, wall placement, reservation, payment or CMS is added.
